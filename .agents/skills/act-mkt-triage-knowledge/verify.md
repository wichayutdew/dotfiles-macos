# Stage: Verify

Perform a separate read-only evidence pass before any retention or page write. Prefer a fresh verifier with complete source references and the proposed records/drafts; if unavailable, the parent performs the pass inline and reports that limitation.

- Reconcile the selected source identities against complete paginated threads and classification outcomes. Every selected ticket has a contribution or explicit no-reusable-knowledge reason. A summary is not a substitute for missing original evidence.
- Check every material diagnosis, fix, ownership claim and operational instruction against its cited source. Keep incident dates, last verification dates, conditions and limitations. Unconfirmed hypotheses belong under unresolved questions, not known resolutions. Verify human/automation attribution against the original source; unspecified origin stays unspecified. Reject invented operational actions, alternatives, prerequisites or diagnostic ordering. Review contradictory and superseded claims explicitly.
- Verify feature reuse and boundaries, multi-feature assignments, stable profile/ticket identity and strict triage/feature page scope and profile-scoped source provenance. Read existing target pages and relevant retained facts before proposing replacement; avoid erasing still-valid earlier knowledge or mixing curator namespaces or unauthorized banks.
- Require all six page sections, correct source links, an adequate source-query/token budget and an assessable readback contract: source links plus critical identifiers, conditions and uncertainty statements. The mechanical page checker supplements this semantic review; matching headings alone is not a pass.
- Confirm the proposed writes affect only the invocation profile's evidence and affected feature pages directly under `triage/`. Page tags are exactly `triage` and `feature:<slug>`; retained evidence additionally keeps its profile tag. No ledger, checkpoint, report/index, Git operation, source Slack/ticket mutation or Confluence update is part of publication. Remove secrets and unnecessary personal details while preserving troubleshooting meaning.

Return `ready` with exact verified ticket records, feature drafts, identities, target IDs and required readback checks. Missing or truncated sources return `sources` → Collect. Unsupported content, wrong feature scope or incomplete draft checks return `content` → Classify. A persistent access or disclosure constraint returns `blocked`. Any material draft/source change invalidates the affected verification and must pass Verify again before Publish.

- Confirm selection used `done_at` within the supplied local-date interval, including tickets opened earlier; reconcile status/date exclusions without treating a missing completion timestamp as a valid exclusion.

# 3. Review and refine

Present the full epic and every story, the source report reference/version, unresolved decisions, and the proposed creation destination. Use chat by default or the user's canonical draft document. Incorporate feedback into that same draft and repeat until the user explicitly approves creation; there is no fixed number of review rounds.

Read-only tracker discovery may establish the target workspace/team/project and supported hierarchy. Use the user's selected system and available capabilities. Show the exact mapping, such as an epic with stories or the tracker's supported project/issue equivalent. Do not silently substitute a different hierarchy or tracker. If target details remain unknown, draft the content first and resolve those details before requesting creation approval.

**Creation gate:** show the complete final draft, tracker/destination, object types, parent/child relationships, and any selected metadata. Ask for explicit approval to create those work items. “The report looks good”, approval of an investigation, initial intent to break work down, silence, or a request to revise the draft is not creation approval. After the final draft is visible, an explicit instruction to create that draft in the named destination is sufficient; do not ask again.

If the user only accepts the content without authorizing creation, retain the draft and clarify whether they want it created. If content, destination, hierarchy, or metadata materially changes after approval, present the changed draft and obtain renewed approval before creating the affected items.

# 3. Review and refine

Present the full epic and every story, the source report reference/version, unresolved decisions, and the proposed creation destination. Preserve the user's canonical draft document and prepare a complete local review artifact. Incorporate feedback into that same draft and repeat until the user explicitly approves creation; there is no fixed number of review rounds. Execute [the Plannotator review procedure](../generic/plannotator-review.md) once the creation proposal is complete; do not finish the turn after merely displaying the draft.

Persist each revised draft and review decision in the same task directory/context, retaining the source investigation fields and separate creation-approval evidence.

Read-only tracker discovery may establish the target workspace/team/project and supported hierarchy. Use the user's selected system and available capabilities. Show the exact mapping, such as an epic with stories or the tracker's supported project/issue equivalent. Do not silently substitute a different hierarchy or tracker. If target details remain unknown, draft the content first and resolve those details before requesting creation approval.

**Creation gate:** show the complete final draft, tracker/destination, object types, parent/child relationships, and any selected metadata. Include an explicit statement that approving this proposal authorizes creating exactly these work items in the named destination, then launch Plannotator for that creation approval. “The report looks good”, approval of an investigation, initial intent to break work down, silence, or a request to revise the draft is not creation approval. After the final draft is visible, an explicit instruction to create that draft in the named destination is sufficient; do not ask again.

After valid creation approval, immediately continue to [create approved items](create.md) and verify them; do not ask for the same approval again. If the user only accepts the content without authorizing creation, retain the draft and clarify whether they want it created. If content, destination, hierarchy, or metadata materially changes after approval, present the changed draft and obtain renewed approval before creating the affected items.

# Stage: Classify

Use complete SQL rows, linked threads and existing feature knowledge. Draft in conversation; mutate nothing.

1. Make one evidence record per rotation+esc_id: original rows, raw statuses, start/incident/verification dates, every Slack coordinate/URL, source revision/latest observed update, symptoms, actions, findings, conditions, ownership and unresolved questions. Numeric status has no assumed meaning. Separate human-confirmed findings, corroborated automated evidence and unconfirmed hypotheses; preserve conflicting metadata and evidence.
2. Search/read canonical feature pages directly under exact top-level `oncall`, with matching oncall+feature tags. Reuse feature slug/title/IDs before creating new kebab-case topics. Match feature/component/failure mode, not rotation, week or title similarity alone. Multiple rotations can enrich one feature; multi-feature escalations may contribute to several pages. Triage-only sources cannot justify oncall guidance. Review untagged legacy pages deliberately before reuse; do not bulk-move historical pages or infer scope from folders alone.
3. Preserve still-valid earlier evidence and conditions. Explicitly qualify or supersede outdated guidance with dated sources. A historical fix is not a current universal rule. Preserve the exact source-supported remediation verbs and their operational meaning; do not invent alternate actions or equate draining with clearing/purging. Preserve who proposed or rejected a hypothesis only when the original source identifies them; an unconfirmed hypothesis does not establish a test or a ruled-out cause. Keep competing explanations under Unresolved questions. An escalation status or an automated suggested fix is not proof of resolution.
4. Draft the six sections in SKILL.md. Include searchable symptoms, source-backed system behavior, diagnostic distinctions and known resolutions with exact prerequisites/limits. Cite literal source links with incident/verification dates. Unsupported sections state what is not established. Merge duplicate guidance without dropping supporting citations or uncertainty.
5. Account for every escalation: feature assignments and contribution, or an evidence-backed no-reusable-knowledge reason. Metadata-only records normally contribute no troubleshooting knowledge and create no placeholder pages. They still count toward source coverage and retain their identity in conversation. A missing existing thread is a Collect gap, not a no-knowledge classification.
6. Prepare one stable complete source document per contributing escalation, using `oncall:<rotation_id>:<esc_id>` and all contributed feature tags. Do not replace the same document separately per feature. Preserve all linked threads/source rows and explicit corrections. If assignments change, plan refreshes for both old and new affected features. Carry exact required citations, critical conditions/identifiers/uncertainty terms, expected oncall parent and full grounded drafts into Verify.

`ready`: every escalation accounted for, canonical targets determined and complete source-backed drafts prepared. `gaps` → Collect for incomplete evidence/counts. `handoff` → resume classification. `blocked`: irreconcilable identity/access/disclosure constraints. A verified no-reusable-knowledge run is a valid no-write outcome.

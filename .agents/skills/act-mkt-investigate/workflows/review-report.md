# Review and refine

The report is ready for user review. Wait for feedback or an explicit statement that the result is accepted/satisfactory; never auto-accept after a timeout or fixed number of rounds. Use chat unless the user requests another review interface.

- **Feedback or new questions:** read the latest canonical report, incorporate the requested changes, research additional evidence where needed, validate, and present the revision. Keep the same report/destination and agreed decisions. This loop continues until the user is satisfied.
- **Clarification needed:** ask the material question and keep independent research moving. Do not revive the old scope-plan gate.
- **Accepted/satisfied:** finish with the accepted report or its path/link and material remaining limitations. Acceptance covers the report only; do not create an epic, stories, or implementation work.
- **Later breakdown request:** use the accepted/current report as input for backlog drafting. Its acceptance does not approve tracker creation; the breakdown has its own explicit creation gate.

Retain the report reference/version, feedback resolved, open limitations, and acceptance evidence for continuation.

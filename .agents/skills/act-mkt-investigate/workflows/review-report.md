# Review and refine

The report is ready for user review. Execute [the Plannotator review procedure](../generic/plannotator-review.md) now and wait for its final decision on the same running session. Never auto-accept after a timeout or fixed number of rounds. An explicit user choice of another review interface takes precedence.

- **Feedback or new questions:** read the latest canonical report, incorporate the requested changes, research additional evidence where needed, validate, present the revision, and launch review again in the same turn. Keep the same report/destination and agreed decisions. This loop continues until the user is satisfied.
- **Clarification needed:** ask the material question and keep independent research moving. Do not revive an upfront scope-plan gate unless explicit user/AGENTS instructions require it.
- **Accepted/satisfied:** finish with the accepted report or its path/link and material remaining limitations. Acceptance covers the report only; do not create an epic, stories, or implementation work.
- **Later breakdown request:** use the accepted/current report as input for backlog drafting. Its acceptance does not approve tracker creation; the breakdown has its own explicit creation gate.

Retain the report reference/version, feedback resolved, open limitations, and acceptance evidence for continuation.

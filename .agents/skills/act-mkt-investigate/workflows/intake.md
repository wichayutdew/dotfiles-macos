# Understand the investigation

Read the user's idea, feature, question, or existing report. Identify the audience, questions to answer, requested depth, known constraints, and supplied sources. Fetch referenced tracker records or documents when relevant; no tracker identifier is required for a standalone idea or general question.

Honor a supplied template. Otherwise choose RFC for a proposal or investigation result for an explanation. Use chat as the default output; reuse the exact existing file/document if the user supplied one. Do not ask for a report path when chat output is sufficient.

When revising, read the latest canonical report and feedback first. Keep accepted decisions, user edits, and protected contracts. Ask only questions whose answers materially affect the investigation; continue research that does not depend on them. Do not insert an upfront scope-plan approval stage.

Carry the full request and readable source references, selected report/template/destination, and material open questions into the [plan step](plan.md), then research. Reading a source does not authorize editing it or creating tickets.
